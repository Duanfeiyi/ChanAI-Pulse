# Step 12：正式 v3.0 UI 实施与人工验收计划

> 最新的逐按钮人工操作步骤以 `STEP_12_MANUAL_REVIEW_GUIDE.md` 为准；本文保留设计范围和完整验收原则。

> 状态：实施中。
> 交付性质：正式 MATLAB 平台界面，不是独立体验 Demo。
> 工作分支：`codex/v3-step-12-formal-ui`。
> 关联需求：V3-REQ-004、V3-REQ-005、V3-REQ-015、V3-REQ-016、V3-REQ-019、V3-REQ-021、V3-REQ-023。

## 1. 本 Step 的产品目标

用户应能在正式平台完成下面这条普通路径：

```text
导入信道文件
→ 看到数据质量、维度与可画图能力
→ 设置内插或外推及精确目标区间
→ 点击“开始预测”
→ 模块二在后台完成标定
→ 模块三完成参数预测与 6GPCM CIR 生成
→ 查看预测 CIR 的合法信道特性并导出
```

三大模块继续保留为三个页面，便于答辩解释和高级使用；但普通用户不需要按页面逐项操作模块二。

## 2. 已冻结的交互决定

| 决定 | 正式实现方式 |
|---|---|
| 页面结构 | 保留模块一、模块二、模块三三个页面；每页维持左侧控制、中间内容、右侧状态/输出的三栏逻辑。 |
| 普通/高级 | 窗口右上角提供全局“普通模式 / 高级模式”切换。普通模式减少选择，高级模式展开可控参数。 |
| 模块二 | 普通模式作为后台流程，第二页显示进度；高级模式才展示生成器、Grid/SA、预算、范围、种子和目标函数。 |
| 任务区间 | 用户优先输入原始样本编号或物理坐标；UI 自动换算内部 MATLAB 一基索引，并在提交前显示解析预览。 |
| 图表 | 模块一和三共用同一注册表与布局；每页按自身真实能力显示 1/3/6/9（可选 +1 热力图），不支持时解释原因。 |
| 模型选择 | 普通模式显示真实的 ModelRegistry 自动选择；当前基线是外推 P6 + Persistence、内插 P8 + Persistence。高级模式可手选兼容模型。 |
| 准确度边界 | 模块三不得显示 Ground Truth、RMSE、NRMSE、准确率或模型排名；这些只属于 Step 13 外部 Benchmark。 |
| 生成器自动选择 | 普通模式先检查 Tx/Rx/Nt 兼容性与后端可用性：SISO 优先 Lite，Lite 不适用时继续检查 Full；只有全部注册的正式候选都不可工作才停止。不得使用 Mock 或改变维度冒充成功。高级用户手动指定时不静默替换。 |

## 3. 实施顺序

### 12.0：状态与设计归档

- 将 Step 11/11ABC 已合并状态写入 GitHub 计划、需求追踪和路线图；
- 归档 v3.1 精度与准确性迭代计划；
- 把早期冻结界面设计中仍有效的原则迁入当前受 Git 管理的 Step 12 文档；
- 不修改 Step 11 的科学逻辑和 Full 6GPCM 核心。

### 12.1：正式 UI 外壳与通用状态

- 建立正式 App 入口，保留现有 App 的可回归路径；
- 实现三页面、普通/高级全局切换、语言切换、窗口缩放和统一状态栏；
- 建立可复用的任务运行状态：未加载、已验证、运行中、已完成、失败、已取消；
- App 回调只负责调用服务与更新状态，不嵌入 Grid、SA、预测或生成科学计算。

### 12.2：模块一正式接入

- 接入 Step 4 的导入、验证、任务创建和坐标/编号换算；
- 接入 Step 5 的能力摘要、注册表和绘图器；
- 显示数据维度、单位/元数据警告、任务预览、已知区与目标区；
- “开始预测”按钮只在数据和任务均有效时启用。
- “开始预测”还要求至少存在一个既兼容当前 Tx/Rx/Nt、又已正确安装/配置的正式生成器；若没有，输入特性仍可查看，但按钮禁用并列出 Lite、Full 的各自原因。

### 12.3：模块二后台编排与专业面板

- 模块一提交后自动调用 Step 6～8 的标定服务；
- 显示准备数据、提取参考特性、策略选择、搜索、生成校准信道、完成/失败；
- 普通模式显示实际算法和简短理由；
- 高级模式支持 `auto/grid/sa`、生成器、范围、预算、种子和目标函数设置；
- `auto` 生成器选择必须遍历当前注册的正式候选并记录候选审计；当前注册项为 Lite 与 Full，QuaDRiGa 在正式 Adapter 完成前不得显示为可用；
- 实现取消、失败、重试和 Manifest 对照；不适用的手动选择必须直接说明原因。

### 12.4：模块三正式接入

- 接入 Step 9～11ABC 的 Request、ModelRegistry、适配、参数预测、Full 6GPCM 生成和 `PredictionResult`；
- 展示真实选中的模型、参数包、选择来源、适配状态、回退原因和生成状态；
- 使用模块一同一图表注册表绘制预测 CIR 特性；
- 显示并导出 CIR、CTF、配置与 Manifest；
- 禁止在正式页面加入准确度图。

### 12.5：自动测试、人工验收与 PR 准备

- 为 UI 到服务的关键调用增加自动冒烟/回归测试；
- 用标准数据、降级数据和 Step 11 的真实预测结果进行人工 GUI 验收；
- 修正审阅发现的问题；
- 仅在项目负责人确认人工验收通过后提交、push 并创建 PR。Codex 不合并 PR。

### 12.F0–F5：四类端到端兼容性补强

- 审计并修复“模块一能画图但模块三不能生成”的能力断层；
- 新增不修改外部核心的可配置 Full 公共 API Adapter；
- SISO自动Lite，MIMO自动Full；资源超限与格式不兼容分开报告；
- 窄带任务不伪造PDP标定，生成结果保持单抽头；
- 独立目标只禁用跨目标热力图，保留目标内部Nt的合法时间/多普勒图；
- 四套标准输入必须分别得到模块三1/3/6/9张标准图并完成导出回读。

## 4. 人工验收前的准备

最终实现完成时，会给出一条可复制的 MATLAB 启动命令和一个固定的正式入口。人工验收应在以下条件下进行：

1. 从 Step 12 工作目录启动，并添加项目路径；
2. 准备 Python Predictor 环境；如测试 Full 后端，再提供外置 Full 6GPCM 根目录；
3. 使用项目内公开的 `demo_data/v3_standard_fixtures/`，不得把私有实测数据写入仓库；
4. 使用中文、英文各进行一次界面检查；
5. 除非明确测试错误路径，正常端到端流程使用已验证的 Lite 或 Full 配置与固定种子。

最终提交人工验收时会提供：启动命令、每个测试输入、建议设置、预期文字/图表和截图位置；不会要求审阅者猜测内部函数名。

## 5. 人工验收清单

### A. 基础外观与通用行为

- [ ] App 能从项目根目录启动，三个模块页面均可打开；
- [ ] 默认中文界面文字不重叠；切换英文后控件不遮挡；
- [ ] 调整窗口大小后，主要按钮、状态和图表仍可见；
- [ ] 普通/高级模式切换明确，普通模式不出现必须填写的专家参数；
- [ ] 页面状态与按钮状态符合当前任务：未加载时不能开始，运行中不允许重复启动，失败后可重试。

### B. 模块一：导入、任务和能力驱动图表

使用以下公开标准数据各至少一次：

| 数据 | 关键检查 |
|---|---|
| `narrowband_static_siso_cir.h5` | 只开放基础展示；空间/时间类图明确说明不可用。 |
| `wideband_static_siso_cir.h5` | 时延/频率组开放，符合 3 图能力。 |
| `wideband_static_mimo_cir.h5` | 时延/频率与空间/角度组开放，符合 6 图能力。 |
| `wideband_dynamic_mimo_cir.h5` | 三组能力开放，符合 9 图；有连续位置轴时可额外出现热力图。 |

- [ ] UI 正确显示 `N_sample、Tx、Rx、Nt、Nf、Npath`，不混淆其含义；
- [ ] 不支持的图不显示伪造曲线，而显示原因，例如缺少阵列几何或连续时间轴；
- [ ] 原始编号/物理坐标输入可转换为内部一基索引；
- [ ] 验收示例：用户填写已知 `0:30,40:60`、目标 `31:39` 时，预览为内部 `1:31,41:61` 与 `32:40`；
- [ ] 越界、重叠、空区间和不可映射坐标会给出可理解错误；
- [ ] 只有任务验证通过时，“开始预测”按钮才启用。

### C. 普通用户端到端流程

- [ ] 在模块一点击一次“开始预测”即可启动后续流程，不需要先去模块二点“开始”；
- [ ] 模块二状态按顺序显示：准备数据、提取参考特性、选择策略、参数标定、生成校准信道、完成/失败；
- [ ] 普通模式显示实际选择的 Grid/SA 和简短理由；
- [ ] 模块三显示实际推荐模型、参数包、模型版本、选择来源和适配状态；
- [ ] 当前冻结注册表测试应如实显示 Persistence，而不能假称 GRU/LSTM/TCN；
- [ ] 外推显示 P6、内插显示 P8；
- [ ] 运行结束后得到预测 CIR/CTF 和合法信道特性图；
- [ ] 模块三页面不出现 Ground Truth、RMSE、NRMSE、准确率、模型排名或真实/预测误差叠加图。

### D. 高级模式：手动覆盖与可追溯性

- [ ] Grid/SA 可选择 `auto/grid/sa`；系统实际执行的方法、来源和理由与 Manifest 一致；
- [ ] 手动 Grid 超过预算时明确拒绝并提示缩小范围或选择 SA，不能静默换成 SA；
- [ ] 手动 SA 时记录“用户指定”；
- [ ] 普通模式自动检查 Lite 与 Full：Lite 不兼容时尝试兼容的 Full，只有二者均不适用才报错；Mock 不进入产品自动候选；
- [ ] 高级模式手动指定 Lite 或 Full 时，若不兼容则直接拒绝并解释，不覆盖用户选择；
- [ ] 可手选兼容预测模型；不兼容模型直接拒绝并说明原因；
- [ ] `AUTO_ADAPT`、`DIRECT`、`EXPERT_ADAPT` 状态清楚，适配未获接受时显示回退理由；
- [ ] 高级选择、随机种子、搜索预算、模型版本和参数来源均写入 Manifest。

### E. 取消、错误和恢复

- [ ] 标定或预测运行中可取消；取消后按钮、缓存和页面状态回到可理解、可重新执行的状态；
- [ ] 无 Python 环境、缺少 Full 6GPCM、非法文件、手动不兼容模型等错误有明确提示；
- [ ] 失败不会把上一次成功结果误标成当前结果；
- [ ] 重试不会静默沿用错误任务的缓存；
- [ ] 不会因为独立预测目标不连续而错误绘制多普勒谱、时间自相关或路线热力图。

### F. 导出和科学边界

- [ ] 可导出 CIR、CTF、生成器配置、预测配置和 Run Manifest；
- [ ] 导出 Manifest 与 UI 显示的任务、算法、模型、参数包、种子和版本一致；
- [ ] 模块二的实测/校准特性对照只称为“标定参考”，不称为预测准确度；
- [ ] 准确度验证入口只说明应使用 Step 13 外部 Benchmark，不在 App 内计算或展示结果。

## 6. 通过标准

人工验收不是只看“界面能打开”。本 Step 通过的最低条件是：

1. 普通用户可用一次主操作完成端到端预测；
2. 高级用户能复核和手动覆盖关键选择；
3. 模块一、二、三显示的状态与底层 Manifest 一致；
4. 图表严格遵守数据能力和连续性限制；
5. 正式页面遵守“生成 CIR 与展示特性，不在产品内评估准确度”的边界；
6. 错误、取消和依赖缺失不会伪造成功或静默降级；
7. 完成人工验收、自动回归和 PR 自审后，才允许请求项目负责人批准提交与创建 PR。
