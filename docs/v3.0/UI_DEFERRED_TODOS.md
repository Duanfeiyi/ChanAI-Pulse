## UI-TODO-001：任务区间编号与真实坐标自动换算

- 来源：Step 4 人工审阅
- 记录日期：2026-07-29
- 计划阶段：Step 12 正式 UI 接入与详细设计
- 当前状态：待实现；不阻塞 Step 4

### 当前情况

Step 4 的底层任务接口使用 MATLAB 数组位置，因此索引从 `1` 开始。
独立 Demo 已支持精确手动区间和多个不连续区间，例如：

```text
已知索引：1:31,41:61
目标索引：32:40
```

这在内部表示用户以 `0` 开始编号时的：

```text
已知样本：0～30、40～60
目标样本：31～39
```

底层能力已经具备，但当前 Demo 要求用户自行完成加一换算，交互不够友好。

### 正式 UI 期望行为

1. 用户按数据文件中的原始样本编号或真实坐标输入区间，不需要了解 MATLAB 从 `1` 开始编号。
2. UI 自动把用户输入换算成内部一基数组位置，再调用现有任务接口。
3. UI 明确显示当前选择依据：
   - 数组位置；
   - 原始样本编号；
   - 道路位置；
   - 时间；
   - 频率。
4. 当文件提供相应物理轴时，允许用位置、时间或频率范围选择目标区。
5. 在提交任务前同时预览“用户输入范围”和“内部解析结果”。
6. 对越界、重叠、空区间以及无法精确映射的坐标给出清晰提示。
7. 不改变 Step 1 已冻结的数据合同和任务合同；换算只发生在 UI/适配层。

### 验收示例

对于原始样本编号 `0～60`，用户输入：

```text
已知：0:30,40:60
目标：31:39
```

正式 UI 应自动生成：

```text
known_indices = [1:31, 41:61]
target_indices = 32:40
```

并在预览中显示目标区严格位于两个已知区之间，任务验证结果为 `PASS`。

## UI-TODO-002：参数优化算法自动选择与高级覆盖

- 来源：Step 7 人工审阅后的算法流程讨论
- 记录日期：2026-07-30
- 对应需求：`V3-REQ-021`
- 后台规则阶段：Step 8
- 正式界面阶段：Step 12
- 当前状态：Step 8 后台 SA 和策略决策器已实现、通过专项测试并由 PR #45 合并；
  正式界面仍待 Step 12

### 默认交互

模块二继续以后台流程为主。普通用户默认只看到：

```text
参数优化：自动
系统选择：Grid Search 或 SA
选择理由：候选数、参数类型、后端成本和计算预算的简要说明
```

高级设置提供：

```text
参数优化方法：
● 自动选择（推荐）
○ Grid Search
○ 模拟退火 SA
```

### 后台决策原则

1. 离散候选明确、完整笛卡尔积较小且符合计算预算时，优先 Grid Search；
2. 参数较多、连续范围较大、组合数超限或生成后端单次成本较高时，优先 SA；
3. 自动决策不能只看上传数据的维度，还要考虑搜索参数、候选规模、生成后端和预算；
4. Step 8 已冻结第一版自动 Grid 组合数上限：Mock 500、Lite 125、Full 16；
   统一手动 Grid 硬上限 500；这些是可配置并写入 Manifest 的工程安全预算；
5. 保存 `requested_strategy`、`selected_strategy`、`selection_source` 和
   `selection_reason`，保证结果可以复查。

### 手动覆盖边界

- 用户指定 Grid 时，若候选数超过安全上限，明确提示缩小范围或改用 SA；
- 用户指定 SA 时，按 SA 执行并记录“用户指定”；
- 不允许用户选择 Grid 后后台偷偷改成 SA；
- 自动选择失败时必须返回明确错误或请求用户调整，不能伪造搜索结果。

### Step 12 验收重点

- 普通模式不要求用户理解算法细节；
- 高级用户可以手动指定算法；
- 界面显示系统实际使用的算法和选择理由；
- 运行结果与 Manifest 中的选择来源一致；
- 模块二不扩张成必须逐项点击的复杂独立页面。

## UI-TODO-003：泛用模型与上传数据微调模式

- 来源：模块三流程讨论与 Step 9 数据契约
- 记录日期：2026-07-30
- 对应需求：`V3-REQ-023`
- 后台阶段：Step 9 定义元数据，Step 10 实现模型与阈值
- 正式界面阶段：Step 12
- 当前状态：Step 10 已实现基础参考权重、自动适配/回退规则；正式 UI 仍待 Step 12

### 正式 UI 期望

普通用户默认看到：

```text
预测模型：泛用预训练模型
上传数据适配：自动（推荐）
```

高级设置允许：

```text
pretrain：只用于离线泛用模型训练
auto：系统根据 Step 10 实验规则判断是否微调
off：本次不微调，直接使用泛用模型
force：用户明确要求尝试微调
```

### 边界

1. `force` 不代表系统可以忽略数据非法、标签失败或资源不足；
2. `auto` 必须记录是否微调及理由；
3. Step 10 在实验前不能随意写死“达到某个样本数就一定微调”；
4. 模块三 UI 不展示 RMSE、NMSE 或 Ground Truth 准确度图；
5. 微调结果、预测参数和后续 CIR 生成的 Manifest 必须能够追溯。

## UI-TODO-004：自动模型选择必须如实显示基线回退

- 来源：Step 11ABC 人工审阅后的模型选择讨论
- 记录日期：2026-08-01
- 对应需求：`V3-REQ-023`
- 正式界面阶段：Step 12
- 当前状态：待实现

### 背景

模型自动选择不是“永远选择神经网络”。当前 Step 11ABC 的冻结选择为：

```text
外推：P6 + Persistence
内插：P8 + Persistence
```

这是当前多路线验证中神经网络未稳定超越简单基线后的安全回退，并不代表未来不能重新训练
GRU、LSTM 或 TCN。

### 正式 UI 期望

普通模式必须显示实际加载的预测器、参数包、版本和简短选择理由，例如：

```text
预测方法：自动推荐
实际选择：Persistence
参数包：外推 P6
原因：当前离线多路线验证中，神经网络尚未稳定超过基线
```

高级模式允许在兼容范围内手动选择 Persistence、Linear、GRU、LSTM 或 TCN；若用户选择的
不是当前注册表推荐项，应明确标记为“用户手动选择，非系统推荐”。模型不兼容时必须拒绝，
不得静默替换。

### 边界

1. 选择理由说明来自离线 ModelRegistry，不是本次任务的 Ground Truth 误差；
2. 模块三仍不显示 RMSE、NRMSE、准确率图或模型排名；
3. 用户上传时不能临时运行多个模型、读取目标区域答案再选择；
4. 未来 v3.1 通过严格验证后可以更新 ModelRegistry；UI 读取新注册表即可，无需伪造或重做页面。
