# 第三方代码与数据政策

> 适用于 ChanAI Pulse v3.0 公开仓库。

## 1. 基本原则

项目负责人允许经确认的第三方资源进入公开仓库，但“允许纳入”不等于可以删除原作者信息、修改许可证或任意修改核心实现。

所有第三方资产必须满足：

- 来源可追溯；
- 许可证或授权状态有记录；
- 原始版权、许可证、NOTICE 和引用信息得到保留；
- 项目新增代码与上游核心代码清楚分离；
- PR 明确列出新增、修改和未修改的文件；
- 不得把论文中的描述当作代码授权；
- 许可证要求比本政策更严格时，以许可证为准。

## 2. 完整版 6GPCM

采用“冻结核心 + 外围适配”方式：

```text
ChanAI Pulse GUI / Core
        ↓
Full6GPCMAdapter（项目新增）
        ↓
配置转换与结果转换（项目新增）
        ↓
完整版 6GPCM 核心（保持原样）
```

允许：

- 新增 Adapter；
- 新增配置结构体；
- 新增输入检查；
- 新增结果转换；
- 新增无界面调用入口；
- 新增测试和示例；
- 增加路径配置和依赖检测。

不允许：

- 为了适配平台直接改写核心算法；
- 删除上游许可证和版权头；
- 把上游代码宣称为 ChanAI Pulse 自主原创；
- 在没有记录的情况下混合项目代码与核心文件；
- 用 6GPCM-lite 的结果冒充完整版 6GPCM 结果。

## 3. 数据

### 可以进入公开仓库

- 小型合成 demo；
- 专门为测试制作的人工 CIR/CTF；
- 已完成授权和匿名化的数据；
- 对应的数据卡、单位、维度和生成说明。

### 默认不进入公开仓库

- 真实测量原始数据；
- 带有敏感位置、设备或采集时间的信息；
- 未确认许可的 SAGE、H5 或模型权重；
- 大型实验输出和临时结果；
- 不能说明来源的数据。

如果未来决定公开真实数据，必须使用单独的数据发布流程，不直接把本地测量目录复制进源码仓库。

## 4. 第三方资产登记最小字段

每项第三方资产至少记录：

```text
name
upstream_source
provider
version
obtained_at
license
allowed_use
allowed_modification
allowed_redistribution
required_attribution
local_path
repository_path
core_files
adapter_files
verification_status
```

## 5. PR 检查

包含第三方资产的 PR 必须回答：

- 资源从哪里获得？
- 使用什么许可证？
- 能否公开分发？
- 哪些是原始核心文件？
- 哪些是 ChanAI Pulse 新增封装？
- 核心文件是否发生变化？
- 是否保留许可证和署名？
- 是否包含数据或权重？
- 文件大小是否适合 Git？

只要其中一项无法解释，PR 就不能标记为“可发布”。

## 7. Step 3 完整版 6GPCM 决定

Step 3 核验的候选包为 `信道生成模块代码_260317.zip`。压缩包中没有发现 `LICENSE`、`NOTICE` 或同类明确许可文件，因此即使项目负责人允许在技术上使用相关资源，当前仍不能证明可以公开再分发全部核心。

本阶段采用：

```text
外置完整版 6GPCM（只读）
      ↓
项目自有无界面探针和结果转换
      ↓
ChanAI Pulse v3 统一 CIR
```

仓库只纳入项目自有的配置、探针、转换器、测试替身、测试和文档，不纳入完整 6GPCM 核心。真实测试通过调用前后文件树 SHA-256 比较证明核心未被改动。

如果后续获得正式许可证、提供者信息和公开再分发授权，可在单独 PR 中重新审阅发布策略；在此之前保持外置。
