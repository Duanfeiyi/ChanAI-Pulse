# Step 14 MAT 转换向导使用说明

## 1. 为什么需要转换向导

平台内部使用统一的 v3 HDF5 数据合同。H5 文件像“整理好的标准资料夹”，变量名称、复数值、维度顺序、物理坐标和单位都有固定位置；MAT 文件更像“用户自己命名的行李箱”，里面可能有 `H`、`cir`、`real/imag`、模型特征甚至只有 PDP 功率。

因此平台不会看到一个 MAT 就盲目猜测，而是采用以下流程：

1. 只读查看变量名、尺寸、类型、是否复数和 MAT 版本；
2. 自动填写高置信度映射；
3. 如果维度含义不明确，要求用户显式确认；
4. 另存为新的标准 v3 H5；
5. 计算源文件哈希，确认转换过程中没有修改源数据；
6. 生成独立 `*.conversion_manifest.json`，记录转换依据；
7. 转换成功后自动回到模块一加载新 H5。

## 2. 支持范围

| 输入 | v3.0 行为 |
|---|---|
| 标准 v3 `.h5/.hdf5` | 不转换，直接进入原有工作流 |
| MAT v7 / v7.3 单个复数变量 | 自动识别或由用户选择变量 |
| 实部、虚部分开的 MAT | 用户明确指定配对变量后组合复数信道 |
| 已知 SAGE MAT 文件夹 | 复用专用 SAGE Adapter；需要时延间隔或带宽 |
| 旧 WiFo HDF5 | 复用专用 WiFo Adapter；明确序列轴语义 |
| 结构明确但维度顺序未知的 MAT | 高级映射：填写 `Tx,Rx,Npath/Nf,Nt,N_sample` 的源顺序 |
| 只有 PDP/DPSD 功率、没有相位 | 可检查，但拒绝伪造完整 CIR/CTF |
| 任意混合 MAT 文件夹 | 不自动批量猜测 |

这里的“支持 MAT”准确含义是：**支持已知结构，以及用户能够明确给出变量和维度含义的 MAT**，不是承诺任何 MAT 都能一键识别。

## 3. 必须明确的项目

- 数据域：CIR（时延域）或 CTF（频域）；
- 复数来源：一个复数变量，或实部/虚部两个变量；
- 源维度顺序：例如 `Tx,Rx,Npath,Nt,N_sample`；
- CIR 的时延：时延变量或时延采样间隔；
- 单位：秒/毫秒/微秒/纳秒，Hz/kHz/MHz/GHz，m/cm/mm/km；
- 可选轴：时间、频率、位置、原始样本编号。

缺少可选物理轴时，转换仍可成功，但平台会诚实降低相应图表能力。例如只有样本序号时，平台不会把 `1:N` 宣称成真实测量时间或道路位置。

## 4. 大文件策略

- 检查阶段优先使用 `whos -file` 和 HDF5 元数据，不先把完整数组读进内存；
- 大型 MAT v7.3 且含 `N_sample` 轴时，转换器按样本块读取；
- 标准 H5 的数值数据集按块写入；
- 较老的 MAT v7 无法像 v7.3 一样可靠随机分块，界面会提示需要足够内存；
- 进度条只显示已确认的阶段和比例，不用伪造百分比掩盖未知耗时。

## 5. 安全与审计

- 永不覆盖源 MAT/H5；
- 永不覆盖已存在的输出 H5 或 Manifest；
- 转换前后计算源文件或 SAGE 文件集合哈希；
- 输出 Manifest 包含映射、读入模式、维度、校验状态和能力分类；
- 功率-only 数据不会被补零相位冒充完整复数信道。
