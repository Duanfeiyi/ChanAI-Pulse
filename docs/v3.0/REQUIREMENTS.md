# ChanAI Pulse v3.0 正式需求

> 基线版本：v3.0-requirements.2
>
> 状态：Step 0 冻结基线
>
> 决策人：`Duanfeiyi`

## 1. 产品目标

ChanAI Pulse v3.0 是一个面向无线信道研究的三模块平台。它接收已有信道信息，完成信道特性分析和内插/外推任务设置；通过 6GPCM 与参数优化生成 CIR；再通过预测器获得目标区域参数并由 6GPCM 生成预测 CIR。

平台的责任边界是：

```text
输入和理解信道数据
        ↓
设置内插或外推任务
        ↓
优化或预测 6GPCM 参数
        ↓
由 6GPCM 生成复数 CIR
        ↓
展示 CIR 对应的信道特性
```

预测准确度由软件外部 Benchmark 验证，不在第三模块 UI 中展示。

## 2. 三个模块

### 2.1 模块一：信道数据输入

模块一必须：

- 导入受支持的信道数据；
- 明确数据是路径域 CIR、频域 CTF，还是需要 Converter 转换的历史格式；
- 检查复数值、维度顺序、坐标轴、单位和元数据；
- 区分 `N_sample`、`Tx`、`Rx`、`Nt`、`Nf` 和 `Npath`；
- 设置内插或外推任务；
- 明确已知区域和目标区域；
- 生成数据能力描述；
- 只展示当前数据真正支持的信道特性图。

模块一不能仅根据数组长度猜测物理含义。例如，100 个独立文件不能自动当作 `Nt=100` 的连续时间序列。

### 2.2 模块二：信道生成

模块二必须：

- 通过统一 Generator Adapter 调用生成器；
- 支持项目已有的 6GPCM-lite；
- 接入完整版 6GPCM；
- 保持完整版 6GPCM 核心实现不变；
- 通过外围配置和 Adapter 传入参数；
- 实现真正的 Grid Search；
- 保留现有随机局部搜索作为对照基线；
- 新增 SA 模拟退火算法；
- 默认由后台根据搜索空间规模、参数类型、生成后端和计算预算，在 Grid Search
  与 SA 之间自动选择；
- 允许高级用户明确指定 Grid Search 或 SA；
- 保存最终使用的算法、选择来源（自动或用户指定）和选择理由；
- 用户指定的方法不适用时必须明确提示，不得静默切换成另一种算法；
- 输出复数路径系数和对应时延；
- 保存生成配置、随机种子、生成器版本和运行记录。

### 2.3 模块三：信道预测

模块三的正式主链路是：

```text
输入信道和内插/外推任务
        ↓
Predictor Adapter
        ↓
目标区域的 6GPCM 参数
        ↓
参数合法性检查
        ↓
完整版 6GPCM
        ↓
预测后的复数 CIR 和 delay
        ↓
统一信道特性引擎
```

模块三必须：

- 支持未来替换 MATLAB 或 Python 预测器；
- 预测适合传给 6GPCM 的参数；
- 调用 6GPCM 生成预测 CIR；
- 使用与模块一相同的图表判断规则；
- 导出 CIR、时延、可选 CTF、配置和运行记录；
- 不显示 Ground Truth、RMSE、NMSE 或其他准确度图。

## 3. 数据维度与可视化原则

平台不采用“固定显示九张图”的做法。图表能力必须由数据内容、坐标轴和元数据共同决定。

| 信道情况 | 典型能力 | 第一版预期图表 |
|---|---|---|
| 窄带静态 SISO | 只有复数信道值 | 功率或功率分布 |
| 宽带静态 SISO | 有频率/时延信息 | PDP、频率自相关、时延扩展 CDF |
| 宽带静态 MIMO | 增加阵列/角度信息 | 上述图 + 角度功率谱、空间相关、角度扩展 CDF |
| 宽带动态 MIMO | 增加真实时间轴 | 上述图 + 多普勒功率谱、时间自相关、多普勒扩展 CDF |

热力图可以将样本或测量路线放在横轴、时延放在纵轴、功率作为颜色，用于观察主径随样本位置或测量过程的变化。

“维度大于 1”只是必要条件，不是充分条件。例如：

- 没有频率坐标或子载波间隔，不能严谨解释频率相关；
- 没有时间间隔，不能严谨计算多普勒；
- 没有阵列几何或角度数据，不能严谨绘制角度功率谱；
- 样本数量不足时，不展示没有统计意义的 CDF。

## 4. MATLAB 与 Python

- GUI 和当前桌面平台继续使用 MATLAB。
- 核心算法允许使用 MATLAB 或 Python。
- GUI 不直接包含算法实现，只调用 Adapter 或核心函数。
- MATLAB 与 Python 必须遵守相同的字段、维度、单位和错误规则。
- 每个正式接口必须提供输入、输出、异常和最小调用示例。
- 更换预测器或生成器时，不应要求重写 GUI。

## 5. 明确不属于 v3.0 必须范围的内容

以下内容可以继续研究，但不作为 v3.0.0 必须验收条件：

- 在正式平台中展示预测准确度；
- 一次性兼容所有历史 MAT/H5 格式；
- 一次性支持所有无线场景和全部频段的实验验证；
- 把 WiFo 作为 v3.0 第一版正式主预测器；
- SAC 强化学习参数优化；
- Web、云端服务或独立安装程序；
- 重做已经冻结的三个页面；
- 根据论文描述直接宣称未经过可运行测试的功能已经完成。

## 6. 需求变更

新增或修改需求必须：

1. 分配新的需求编号或修订原编号；
2. 在需求追踪表中登记；
3. 说明影响的模块和接口；
4. 增加或更新验收测试；
5. 通过 PR 由 `Duanfeiyi` 批准。
