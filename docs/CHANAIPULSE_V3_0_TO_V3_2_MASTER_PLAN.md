## 3. v3.0.0：正式平台基线

### 3.1 版本目标

v3.0 的目标是先建立可信、可追溯、能够生成预测 CIR/CTF 的完整产品链路，而不是提前宣称神经网络已经在所有场景中优于简单基线。

```text
标准数据输入
→ 信道特性分析
→ 生成器参数标定
→ 目标区参数预测
→ 6GPCM 生成 CIR/CTF
→ 结果导出
→ 独立 ChannelBenchmark 评价
```

### 3.2 已完成功能

- ✅ `ChannelSimulator`：负责导入、表征、标定、预测、生成和导出。
- ✅ `ChannelBenchmark`：独立读取完整 Ground Truth，对预测结果进行严格对齐和准确度评价。
- ✅ MATLAB 三页正式 UI，支持中文/English、普通/高级模式。
- ✅ 标准 CIR/CTF HDF5 合同：
  - CIR：`Tx × Rx × Npath × Nt × N_sample`；
  - CTF：`Tx × Rx × Nf × Nt × N_sample`。
- ✅ MAT v7/v7.3 转换向导，支持复数变量、实部/虚部配对、显式维度映射、SAGE 文件夹和旧 WiFo HDF5。
- ✅ 转换过程保持源文件不变，拒绝覆盖既有输出；不能从 power-only 数据虚构复数相位。
- ✅ 1/3/6/9 类信道特性图按数据能力开放，不支持的图不会伪造。
- ✅ 样本/位置轴内插与外推任务，以及物理坐标到 MATLAB 索引的映射。
- ✅ Grid Search、模拟退火 SA、自动推荐和高级手动覆盖。
- ✅ 6GPCM-Lite 与 Full 6GPCM Adapter 的逐候选兼容性检查。
- ✅ P2/P4/P6/P8 参数顺序和预测/生成合同。
- ✅ 正式产品冻结为：
  - 外推：P6 + Persistence；
  - 内插：P8 + Persistence；
  - 预测端不读取目标区域 Ground Truth。
- ✅ 预测参数到 CIR/CTF 的生成、导出和 Manifest 追溯。
- ✅ Benchmark 支持复数 NMSE/相关性、PDP/时延、空间/角度、时间/多普勒等能力相关指标。
- ✅ Step 14 自动回归和项目负责人人工验收。

### 3.4 v3.0 的诚实边界

- GRU/LSTM/TCN 已有可调用、可训练、可测试的研究骨架，但尚未通过正式多路线、多随机种子准入门槛。
- 正式目标预测主要是样本/位置轴任务；Time/Frequency 目前能导入、展示或参与部分特性计算，但尚不是完整的一等目标预测任务。
- P6/P8 是工程基线，不代表已经证明它们在所有场景中最优。
- QuaDRiGa 尚不是正式注册的生产生成器。
- 准确度结论只能来自独立 `ChannelBenchmark`，不能由正式预测 UI 自行给出。

## 5. v3.2：Time / Space / Frequency 三维信道预测

### 5.1 版本定位

v3.2 将预测维度提升为正式的一等任务：

- **Time**：根据过去一段时间的信道状态预测未来时刻，或恢复时间轴内部缺失区间；
- **Space**：根据已知位置/轨迹预测未知位置，是 v3.0 样本/位置任务的统一和升级；
- **Frequency**：根据部分频点/子载波恢复目标频率网格，并研究跨中心频率/跨频段泛化；
- **端到端闭环**：预测信道参数后调用 Full 6GPCM，生成目标 CIR/CTF，并在独立 Benchmark 中比较。

v3.2 不把“由同一 CIR 计算一组 CTF 频点”误称为“预测了另一个传播环境或另一个载频”。带内频率恢复与跨频段预测必须分开定义和报告。

### 5.2 v3.2-0：冻结三维任务合同

**状态：⬜ 已规划，未开始。**

- 为 `TaskRequest` 增加正式预测轴：`time`、`space`、`frequency`；
- 统一已知区、目标区、输入坐标、目标坐标、内插/外推、单步/多步语义；
- 扩展 `PredictionResult`、Manifest、坐标映射和输出形状；
- 统一 CIR/CTF/参数序列在三个轴上的布局与单位；
- 定义模型能力声明，例如支持哪些轴、哪些参数包、是否因果、是否支持插值；
- 定义 Benchmark 严格对齐规则，防止时间、位置或频率坐标错位。

完成标准：三个维度使用同一套可扩展接口，现有 Space 任务保持兼容。

主要工作：

- 将分时刻、分位置或分频率的 P2/P4/P6/P8/扩展参数映射给外围 Adapter；
- 支持目标时间、目标位置、Tx/Rx 动态轨迹和指定频率网格；
- Time 路径处理参数连续性、簇出生/消失、相位连续性和多普勒一致性；
- Space 路径处理位置坐标、轨迹连续性和空间相关；
- Frequency 路径区分带内 CTF 恢复与跨载频参数预测；
- 参数越界或生成器不兼容时提供可解释错误或已登记回退；
- Full 6GPCM 核心继续保持原样，只扩展 ChanAI Pulse 外围 Adapter。

完成标准：三个维度都能完成“输入 → 预测参数 → Full 6GPCM → CIR/CTF”的可审计端到端运行。

### 5.6 v3.2-4：正式 UI、三维 Benchmark 与发布验收

**状态：⬜ 已规划，未开始。**

正式 UI：

- 选择 Time、Space 或 Frequency；
- 设置已知区和目标区；
- 设置时间步长、空间坐标/距离或频率网格；
- 选择内插/外推、模型和参数包；
- 展示预测结果及生成的 CIR/CTF；
- 导出 PredictionResult、CIR/CTF、配置和 Manifest。

独立 Benchmark：

- Time：多步误差、时间相关性、连续性、CIR/CTF 和多普勒指标；
- Space：不同距离的预测误差、空间相关、位置插值/外推和 CIR/CTF 指标；
- Frequency：复数频域误差、幅度/相位、缺失子载波恢复和频率相关性；
- 带内预测和跨频段实验必须分开报告；
- 所有轴继续使用严格坐标、维度和单位对齐。

发布验收：

- 三轴自动回归；
- 正式 UI 隐藏运行和人工验收；
- Lite/Full 兼容性与回退测试；
- 新 Clone、ZIP 解压路径和中英文路径测试；
- 中英文文档、限制和 Release Notes；
- 由项目负责人手动合并 PR，并决定是否创建 `v3.2.0` Tag/Release。

## 6. 跨版本依赖关系

| 后续能力 | 依赖的前置工作 |
|---|---|
| v3.1 模型公平比较 | v3.1-2 的数据版本与 Experiment Manager |
| v3.1 ModelRegistry v2 | v3.1-3 参数包与 v3.1-4 模型准入结果 |

| v3.2 三维训练 | v3.1 数据管理、实验复现和模型注册基础 |

| v3.2 Frequency 正式能力 | 明确频率坐标的带内数据与严格 Benchmark |
| v3.2 跨频段实验 | 多载频配对数据及物理一致性验证 |

因此推荐顺序保持为：先完成 v3.1，再进入 v3.2。v3.2 可以提前冻结合同和数据需求，但不应绕过 v3.1 的实验管理、模型准入和端到端验证基础。

## 7. 长期工程规则

- 所有 PR 只能由项目负责人手动合并；Codex 不执行 merge。
- Tag 和 GitHub Release 由项目负责人决定并手动创建，除非以后另有明确授权。
- Full 6GPCM 核心保持原样，所有接口化工作位于外围 Adapter。
- 不覆盖、移动或删除桌面源文件。
- 不向 GitHub 上传私有实测数据、缓存、checkpoint 或大型实验输出。
- 大型训练资产保存在 Git 外的工作资产目录；仓库只保存可审查代码、配置、Manifest、小型 fixture 和摘要。
- 产品预测路径不得读取目标区域 Ground Truth；准确度评价继续由独立 `ChannelBenchmark` 完成。
- 新模型只有在相同数据、相同划分、多随机种子和端到端 Benchmark 下通过门槛后，才能进入正式 Registry。
