## 3. v3.0.0：正式平台基线

### 3.1 版本目标

v3.0 的目标是先建立可信、可追溯、能够生成预测 CIR/CTF 的完整产品链路，而不是提前宣称神经网络已经在所有场景中优于简单基线。

```text
标准数据输入
→ 信道特性分析
→ 生成器参数标定
→ 目标区参数预测
→ 6GPCM 生成 CIR/CTF
→ 结果导出
→ 独立 ChannelBenchmark 评价
```

### 3.2 已完成功能

- ✅ `ChannelSimulator`：负责导入、表征、标定、预测、生成和导出。
- ✅ `ChannelBenchmark`：独立读取完整 Ground Truth，对预测结果进行严格对齐和准确度评价。
- ✅ MATLAB 三页正式 UI，支持中文/English、普通/高级模式。
- ✅ 标准 CIR/CTF HDF5 合同：
  - CIR：`Tx × Rx × Npath × Nt × N_sample`；
  - CTF：`Tx × Rx × Nf × Nt × N_sample`。
- ✅ MAT v7/v7.3 转换向导，支持复数变量、实部/虚部配对、显式维度映射、SAGE 文件夹和旧 WiFo HDF5。
- ✅ 转换过程保持源文件不变，拒绝覆盖既有输出；不能从 power-only 数据虚构复数相位。
- ✅ 1/3/6/9 类信道特性图按数据能力开放，不支持的图不会伪造。
- ✅ 样本/位置轴内插与外推任务，以及物理坐标到 MATLAB 索引的映射。
- ✅ Grid Search、模拟退火 SA、自动推荐和高级手动覆盖。
- ✅ 6GPCM-Lite 与 Full 6GPCM Adapter 的逐候选兼容性检查。
- ✅ P2/P4/P6/P8 参数顺序和预测/生成合同。
- ✅ 正式产品冻结为：
  - 外推：P6 + Persistence；
  - 内插：P8 + Persistence；
  - 预测端不读取目标区域 Ground Truth。
- ✅ 预测参数到 CIR/CTF 的生成、导出和 Manifest 追溯。
- ✅ Benchmark 支持复数 NMSE/相关性、PDP/时延、空间/角度、时间/多普勒等能力相关指标。
- ✅ Step 14 自动回归和项目负责人人工验收。

### 3.4 v3.0 的诚实边界

- GRU/LSTM/TCN 已有可调用、可训练、可测试的研究骨架，但尚未通过正式多路线、多随机种子准入门槛。
- 正式目标预测主要是样本/位置轴任务；Time/Frequency 目前能导入、展示或参与部分特性计算，但尚不是完整的一等目标预测任务。
- P6/P8 是工程基线，不代表已经证明它们在所有场景中最优。
- QuaDRiGa 尚不是正式注册的生产生成器。
- 准确度结论只能来自独立 `ChannelBenchmark`，不能由正式预测 UI 自行给出。

### 4.5 v3.1-3：参数敏感度、消融与参数包冻结

**状态：✅ 已完成正式本地证据研究，PR #70 已由项目负责人手动合并。**

- 在统一条件下比较 P2/P4/P6/P8；
- 固定生成器随机种子，每次只扰动一个参数；
- 评价参数误差对复数 CIR、CTF、PDP、RMS 时延扩展、角度、空间相关和多普勒的影响；
- 进行删除参数的消融实验；
- 只有标签可靠、单位明确、可以归一化、能够映射到生成器且端到端有收益的参数才能进入正式包；
- P8 稳定后，再研究角度、空间相关、多普勒和簇出生/消失等扩展参数。

完成标准：冻结经过证据支持的正式参数包，而不是默认“参数越多越好”。

已完成的本地证据结论：在完整 v3.1-2 语料的无泄漏 Persistence 诊断和三种公开 Full 6GPCM profile、三组固定种子、72 组单参数对照下，P6 仅覆盖约 73.7% 综合敏感度，低于外推 85% 门槛。因此，v3.1-3 为后续训练冻结 **P8（内插）/ P8（外推）**。该决定不追溯修改 v3.0.0 的已发布 P6/P8 Persistence 产品基线；最终独立端到端准确度仍由 v3.1-6 负责。

## 5. v3.2：Time / Space / Frequency 三维信道预测

### 5.1 版本定位

v3.2 将预测维度提升为正式的一等任务：

- **Time**：根据过去一段时间的信道状态预测未来时刻，或恢复时间轴内部缺失区间；
- **Space**：根据已知位置/轨迹预测未知位置，是 v3.0 样本/位置任务的统一和升级；
- **Frequency**：根据部分频点/子载波恢复目标频率网格，并研究跨中心频率/跨频段泛化；
- **端到端闭环**：预测信道参数后调用 Full 6GPCM，生成目标 CIR/CTF，并在独立 Benchmark 中比较。

v3.2 不把“由同一 CIR 计算一组 CTF 频点”误称为“预测了另一个传播环境或另一个载频”。带内频率恢复与跨频段预测必须分开定义和报告。

## 6. v3.3：本地智能体与自然语言配置助手

### 6.1 版本定位

v3.3 在 v3.2 已完成 Time / Space / Frequency 一等预测能力的基础上，为 `ChannelSimulator` 增加本地、离线、可控的自然语言操作入口。它不是替代现有普通/高级模式的通用聊天机器人，而是 ChanAI Pulse 的“自然语言配置层”：用户描述目标，智能体负责理解、检查、解释和准备配置；确定性平台负责识别事实、验证规则和执行受控修改；用户保留最终运行权。

v3.3 的目标是让不熟悉信道建模、模型合同和平台参数的普通用户也能完成：

- 解释上传 MAT/HDF5 等数据的格式、组成、维度、坐标轴和能力；
- 区分 CIR、CTF、PDP、DPSD、SAGE、WiFo 等输入类型；
- 推荐内插/外推、Time / Space / Frequency / Sample 任务轴和已知/目标区间；
- 查询与当前任务、参数包、输入形状和 checkpoint 合同兼容的模型；
- 推荐 Lite/Full 6GPCM 和 Grid/SA 等策略；
- 生成配置差异，经用户确认后填写平台设置，并允许一键撤销；
- 解释错误、定位并高亮控件，引导用户完成后续按钮操作。

v3.3 主要降低误配置概率和学习成本，不直接提高 GRU、LSTM、TCN 或 6GPCM 的数学精度。相同配置下，开启与关闭智能体必须得到一致的预测结果。

### 6.2 产品边界与基本原则

1. **本地离线**：默认不向外部网络发送聊天、路径、数据摘要、配置、原始信道数据或预测结果。
2. **确定性程序负责事实**：文件格式、维度、坐标、能力、模型和 checkpoint 兼容性由现有检查器、合同、Registry 和 Validator 判断；LLM 负责理解和解释，不得覆盖硬规则。
3. **不读取原始大型矩阵**：LLM 只接收经过脱敏和裁剪的结构化摘要，不直接接收整个 MAT/HDF5 数值载荷。
4. **所有修改可见、可确认、可撤销**：智能体不得静默修改平台状态。
5. **可选增强模块**：未安装模型、模型启动失败或用户关闭助手时，`ChannelSimulator`、`ChannelBenchmark` 和 6GPCM 流程仍须正常运行。
6. **产品预测与 Benchmark 隔离不变**：智能体不能读取目标区域 Ground Truth，也不能代替独立 Benchmark 给出准确度结论。
7. **Full 6GPCM 核心不变**：智能体只能通过 ChanAI Pulse 外围 Adapter 和正式配置接口工作。

v3.3 默认不允许智能体：

- 执行任意 MATLAB、Python、PowerShell 或 Shell 代码；
- 任意读取、删除、移动、覆盖或上传用户文件；
- 修改 Full 6GPCM 核心、checkpoint 或模型权重；
- 绕过 Registry、Schema、Validator 或预检强制应用设置；
- 根据文件名或矩阵形状擅自断定维度语义；
- 从 PDP/DPSD 等 power-only 数据虚构复数相位；
- 未经用户确认修改配置；
- 在第一版中自行启动训练、正式预测或大型 6GPCM 生成。

### 6.3 悬浮智能体 UI

正式入口位于 ChannelSimulator 主界面右下角。按钮状态包括：绿色表示本地模型可用，灰色表示未安装或未启动，蓝色动画表示正在分析，黄色角标表示等待确认，红色表示本地模型或工具错误。

点击后从右侧展开主界面内的浮动对话面板，建议占主窗口宽度的 25%～35%，支持展开、收起、调整宽度、关闭、停止生成和新建会话。面板至少包含：

- 智能体名称、本地/离线状态和当前模型；
- 当前上传数据及分析状态；
- 简洁对话消息和输入框；
- 根据当前状态变化的快捷问题；
- 配置修改卡片及修改原因；
- `查看详细修改`、`应用设置`、`取消`、`撤销本次修改`；
- 控件定位、高亮和操作引导；
- 模型未安装时的轻量/推荐模型安装或已有服务连接入口。

任务完成后的默认回答保持简短，例如：

```text
已完成：任务设置为时间轴外推，使用前 80% 预测后 20%。
模型保持 Auto，平台会从兼容模型中选择。
配置已通过检查，请点击“开始预测”。
```

用户要求“详细解释”时，再展示数据证据、Registry 结果、规则依据和警告。

### 6.4 权限等级

| 等级 | 能力 | 是否需要确认 |
|---|---|---|
| Level 1：解释 | 解释术语、数据摘要、设置、模型和错误 | 否 |
| Level 2：导航 | 展开相关区域、定位并高亮控件、指导点击 | 否，但不得修改配置 |
| Level 3：提案 | 生成类型化配置方案和修改差异 | 仅生成提案不需要；不得直接应用 |
| Level 4：应用 | 通过正式 Config Patch 接口应用并保存撤销快照 | 是 |
| Level 5：运行 | 启动训练、预测或大型生成 | v3.3 默认关闭，由用户亲自点击 |

普通用户默认开启解释、导航和配置提案；应用设置需要一次性确认；自动运行、文件修改、网络访问和长期保存聊天记录默认关闭。

### 6.5 端到端工作流

```text
上传数据
→ 确定性数据检查器只读分析
→ 生成脱敏 ChannelDataSummary
→ 用户在悬浮窗描述目标
→ LLM 读取数据摘要、当前配置、平台能力和本地知识
→ LLM 调用白名单工具查询任务、模型、checkpoint 和生成器兼容性
→ 生成结构化 ConfigurationProposal
→ Policy/Validation Engine 独立验证
→ 存在歧义时解释并追问；存在硬冲突时拒绝应用
→ 验证通过后展示修改差异
→ 用户确认
→ Config Patch Adapter 应用类型化设置并保存旧快照
→ 现有预检再次检查
→ 智能体简短说明结果并引导用户点击运行按钮
```

更换上传文件后，旧数据结论和待确认提案必须失效，防止跨文件污染。

### 6.6 核心合同和白名单工具

v3.3 冻结以下四类核心合同：

- `ChannelDataSummary`：格式、版本、哈希、CIR/CTF/PDP/DPSD/SAGE/WiFo 分类、复数状态、Tx/Rx/Path/Frequency/Time/Sample 维度、坐标、单位、排序、宽带/MIMO 能力、可用任务、缺失信息和警告；

### 6.7 本地模型、运行时和资源策略

v3.3 使用可替换的 Provider，而不是把产品绑定到单一运行程序：

```text
LocalLlmProvider
├── OllamaProvider
├── LlamaCppProvider
├── LMStudioProvider（可选）
└── DisabledProvider
```

当前候选档位为：

| 档位 | 当前候选 | 模型文件 | 运行占用工程估算 | 推荐整机内存 | 定位 |
|---|---|---:|---:|---:|---|
| 轻量 | Qwen3-4B Q4_K_M | 约 2.5 GB | 约 4～6 GB RAM | 16 GB | 基本问答、导航和受约束配置 |
| 推荐 | Qwen3-8B Q4_K_M | 约 5.0～5.2 GB | 约 7～10 GB RAM | 32 GB；16 GB 偏紧 | 更可靠的中文、多轮追问和工具调用 |
| 增强 | 约 14B 的兼容 Q4 模型 | 约 9 GB 起 | 约 12～18 GB RAM | 32～64 GB | 高配置设备可选，不作为默认依赖 |

上述运行占用按 8K～16K 上下文估算，实际取决于后端、上下文、CPU/GPU 分配和 KV Cache。正式开发时必须使用 ChanAI 专项评测重新比较届时成熟的 Qwen3.5 等候选，当前型号不作为永久锁定。

模型权重不直接进入 Git 主仓库。仓库保存 Provider、配置、安装器和模型 Manifest；权重通过独立 Release Asset、受控下载或用户已有 Ollama/llama.cpp 服务提供，并登记名称、版本、来源、许可证和 SHA-256。

资源管理器必须：

- 检测系统 RAM、GPU、显存及 MATLAB/PyTorch 当前资源；
- 推荐轻量、推荐或禁用档位；
- 选择 CPU、GPU 或混合模式并限制上下文；
- 空闲后休眠或卸载模型；
- 启动神经网络训练/预测前释放 LLM 显存；
- 任务结束后按需重新加载；
- 内存不足时安全降级，不影响主平台；
- 防止多个大模型重复加载并在浮窗显示加载、休眠和错误状态。

本地知识检索第一版优先使用结构化索引、关键词、错误码和 Registry 查询；后续可选约 0.6B 的轻量 Embedding 模型，但不作为强制依赖。

### 6.9 v3.3 验收标准

- 未安装模型或关闭助手时，原平台正常启动和运行；
- 未经确认的配置写入为 0；
- 所有 Config Patch 通过 Schema 和确定性 Validator；
- 标准文件摘要与确定性检查器一致；
- 轴、单位或维度不明确时必须追问，不能猜测；
- 不兼容模型和 checkpoint 不能应用；
- 所有助手修改均可准确撤销；
- 原始大型信道载荷不进入 LLM 上下文；
- 默认无外部网络数据传输；
- 不允许任意代码、文件操作或修改 Full 6GPCM 核心；
- LLM 崩溃、超时或内存不足不导致主平台退出；
- 更换文件后不沿用旧数据结论；
- 相同配置下，助手开关不改变预测结果；
- 神经网络任务开始前能够释放 LLM 占用的显存；
- 支持中文自然语言和主要英文专业术语。

内部评测目标：结构化输出合法率 100%，未确认写入 0，配置应用/撤销一致率 100%，安全用例阻断率 100%，标准摘要一致率 100%，核心意图识别准确率目标不低于 95%，合法工具调用成功率目标不低于 98%。最终指标以 ChanAI 自建测试集和真实硬件证据为准。

### 6.10 v3.3 完成后的用户工作流

普通用户：

```text
上传文件
→ 输入“帮我用前 80% 预测后 20%”
→ 查看数据解释和配置差异
→ 确认应用
→ 点击开始预测
```

高级用户：

```text
手动设置模型和参数
→ 输入“检查当前配置是否兼容”
→ 查看冲突、证据和建议
→ 决定是否应用或保持原设置
```

错误处理：

```text
出现错误
→ 询问智能体
→ 获得通俗解释
→ 智能体定位并高亮相关控件
→ 用户确认修正后继续
```

## 8. 长期工程规则

- 所有 PR 只能由项目负责人手动合并；Codex 不执行 merge。
- Tag 和 GitHub Release 由项目负责人决定并手动创建，除非以后另有明确授权。
- Full 6GPCM 核心保持原样，所有接口化工作位于外围 Adapter。
- 不覆盖、移动或删除桌面源文件。
- 不向 GitHub 上传私有实测数据、缓存、搜索/中间 checkpoint 或大型实验输出；经正式筛选、哈希绑定且批准随产品发布的小型官方 checkpoint 可以进入版本化模型包。
- 大型训练资产保存在 Git 外的工作资产目录；仓库只保存可审查代码、配置、Manifest、小型 fixture 和摘要。
- 产品预测路径不得读取目标区域 Ground Truth；准确度评价继续由独立 `ChannelBenchmark` 完成。
- 新模型只有在相同数据、相同划分、多随机种子和端到端 Benchmark 下通过门槛后，才能进入正式 Registry。
- 本地 LLM 是可选增强模块，不得成为 ChannelSimulator、ChannelBenchmark 或 6GPCM 的强制启动依赖。
- LLM 权重不直接进入 Git 主仓库；通过独立模型包或受控下载提供，并登记来源、许可证、版本和哈希。
- 原始大型信道数据不得进入 LLM 上下文；LLM 默认只接收脱敏结构化摘要。
- LLM 只能调用白名单工具和类型化配置接口；未经用户确认不得应用设置，默认不得启动训练、预测或大型生成。
- 本地智能体不得改变产品预测与独立 Benchmark 的隔离边界，也不得影响相同配置下的数值结果。
