# ChanAI Pulse v3.1：预测精度与准确性迭代计划

> 状态：规划中；在 v3.0 正式平台、外部 Benchmark 和发布验收完成后启动。
> 版本定位：v3.1 是在 v3.0 稳定平台基础上的**预测精度、科学验证与零配置分发迭代**，不是重新设计平台 UI。
> 关联：`docs/v3.0后续工作Steps.md` 的 Step 11A/11B/11C、Step 13、Step 14。

## 1. 为什么需要 v3.1

v3.0 的首要目标是建立可信、可追溯、能生成预测 CIR 的完整平台链路：

```text
输入信道和任务
→ 参数标定
→ 参数预测
→ 6GPCM 生成预测 CIR
→ 合法信道特性展示与导出
```

当前 Step 11ABC 的验证结果中，自动选择了 `Persistence`（延续最后一个已知值）作为默认预测器。它并不是“AI 功能失败”，而是说明当前合成路线平滑、预测跨度短时，简单基线尚未被 GRU、LSTM、TCN 稳定超越。

v3.1 的任务就是在更多数据、更严格的验证和更完整的参数目标下，判断神经网络能否真正、稳定地超过基线；只有证据充分时，才升级系统的默认模型。

## 2. v3.1 的边界

### 要做

- 扩充泛用预训练数据、场景和路线覆盖；
- 将已确认可公开分发的完整 Full 6GPCM 工作软件包（含必要静态资源）直接纳入仓库，使普通用户下载后无需手动配置 6GPCM 路径；
- 提升 GRU、LSTM、TCN 及经验证研究型候选的预测精度；
- 扩展预测参数包；
- 建立更严格的 ModelRegistry v2；
- 通过软件外部 Benchmark 验证“参数 → CIR → 特性”的端到端质量；
- 在不改变普通用户操作习惯的前提下，让正式 UI 显示新的真实推荐模型和理由。

### 不做

- 不因为 v3.1 而改变 v3.0 的 CIR/CTF 数据合同；
- 不把 Ground Truth、RMSE、NRMSE 或模型排名放入正式模块三；
- 不修改完整版 6GPCM 核心；
- 不把完整版 6GPCM 做成普通用户必须额外拉取的 Git Submodule，也不要求普通用户手动填写 `EngineRoot`；
- 不把私有实测数据、受限数据或大规模训练资产上传到公开 Git；
- 不保证“必须由神经网络取代 Persistence”。基线持续胜出时，继续使用基线是正确结果。

## 3. 自动模型选择：未来怎样从 Persistence 升级为 GRU、LSTM 或 TCN

这里有两个不同层次：

| 层次 | 做什么 | 不能做什么 |
|---|---|---|
| 离线训练与验证 | 用冻结的训练/验证路线比较模型，生成新版 ModelRegistry | 不能用最终测试集反复调参 |
| 用户实际预测 | 根据任务与数据合同读取已经冻结的推荐模型 | 不能读取本次目标区域真实答案后临时挑模型 |

### 3.1 离线比较流程

对每个兼容组合独立比较：

```text
任务类型（内插/外推）
× 参数包（P2/P4/P6/P8 或后续扩展包）
× 场景/数据版本
× 模型（Persistence、Linear、GRU、LSTM、TCN）
```

每个神经网络至少使用多个随机种子，并在路线级、场景级隔离的验证数据上比较。比较时同时看：平均误差、最差路线、胜出路线比例、随机种子波动、推理成本和端到端 CIR 特性。

### 3.2 第一版升级门槛

沿用 Step 11ABC 已冻结的安全门槛，直到 v3.1 启动会议正式调整：

1. 神经网络的平均 NRMSE 至少比最佳简单基线改善 10%；
2. 至少在 60% 的验证路线中胜出；
3. 任一路线的误差不得超过基线的 2 倍；
4. 多随机种子结果不能明显不稳定；
5. 经过 `预测参数 → 6GPCM → CIR/CTF → 信道特性` 的端到端检查后仍然合格；
6. 上述选择完成后冻结，最终 Test 只负责评分，不能倒回去继续挑模型。

满足全部条件的候选中，再按验证表现、最差路线表现、稳定性和资源成本选择最佳模型。例如：

```text
外推 + P6：TCN 满足全部门槛且综合最佳 → 自动推荐 TCN
内插 + P8：LSTM 满足全部门槛且综合最佳 → 自动推荐 LSTM
某任务没有神经网络过线 → 自动推荐 Persistence 或 Linear
```

这份结果写入版本化 `ModelRegistry`。正式 UI 只显示注册表的真实选择和简短理由，不能为了看起来更“AI”而隐藏基线。

## 4. 工作包

### v3.1-0：建立可比较的 v3.0 基线

- 固定 v3.0 发布版本、数据合同、Step 13 Benchmark 与模型/生成器 Manifest；
- 保存当前外推 P6 + Persistence、内插 P8 + Persistence 的基线报告；

**完成标准：** 同一输入可以复现 v3.0 基线结果；没有人可以通过更换测试划分来“制造提升”。

### v3.1-1：内置完整版 6GPCM，实现下载即用

在已经确认完整版 6GPCM 可以随项目公开分发的前提下，采用**源码直接随仓库管理**的方式，
不使用容易在普通下载或 ZIP 包中缺失内容的 Git Submodule。

- 将已确认可公开分发的完整 Full 6GPCM 工作软件包（含必要静态资源、说明文档和示例）放入 `third_party/full_6gpcm/`；
- 保留上游目录结构和核心实现，ChanAI Pulse 只通过外围 Adapter 调用，不直接改写其核心算法；
- 在第三方目录保持核心文件原样，并记录固定版本和完整性哈希；
- 普通模式从 `ChannelSimulator.m` 所在项目根目录自动定位内置 6GPCM，不显示路径配置步骤；
- 高级模式仍可显式指定外部 `EngineRoot`，便于开发者测试其他版本，但这只是可选覆盖，不是运行前提；
- 生成器自动选择继续检查任务维度和实际可用性；内置 Full 6GPCM 兼容时直接使用，不兼容时继续尝试其他候选，全部候选失败后才报错；
- 对 SISO/MIMO、静态/动态等 1/3/6/9 图对应标准样例执行生成器冒烟和端到端回归；
- 第三方源码进入 Git，但训练语料、运行缓存、临时结果和大规模生成数据仍放在工作资产目录并由 `.gitignore` 排除；
- Full 6GPCM 上游升级必须通过独立 PR：更新版本与哈希、审查核心差异、运行 Adapter 和端到端回归后再替换。

建议的仓库结构：

```text
third_party/
└─ full_6gpcm/
   ├─ <完整工作软件包、必要静态资源、说明与示例>
   └─ <核心文件保持原样；完整性哈希记录在 v3.1-1 文档>
```

**完成标准：** 用户通过 Git Clone 或 GitHub ZIP 获得完整项目后，只需满足 MATLAB/Python 等平台运行环境，
即可从 `ChannelSimulator.m` 启动并调用 Full 6GPCM；无需另行下载 6GPCM、搜索本机目录或手动添加地址。

### v3.1-2：扩充训练与验证语料

- 以完整 6GPCM 公共 API 的多场景、多频段 profile 派生参数为主要可公开复现来源，并明确它与逐路线 CIR 生成的区别；
- v3.1-2 增加更长的确定性平滑参数路线和 LOS/NLOS 场景；速度、Tx/Rx 天线数只作为目录元数据，不宣称参与参数标签生成；
- 按速度和天线配置实际生成 CIR/CTF，以及突变、遮挡、动态和空间变化，分别在参数敏感度与独立端到端 Benchmark 中完成；
- 实测数据仅在取得授权后用于本地外部验证或明确隔离的适配研究；
- 继续按路线/场景组切分，禁止相邻滑窗跨 Train/Validation/Test；
- 所有训练数据下载、缓存和派生训练资产保存到 D 盘工作资产目录，不进入 Git；本条不包含 v3.1-1 已批准随仓库分发的 Full 6GPCM 运行源码与必要静态资源。

**完成标准：** 参数语料版本、来源、分组切分和规模可追溯；能力边界写入 provenance；训练/验证/测试没有泄漏。

### v3.1-3：扩展预测目标参数

v3.0 已冻结 `P2/P4/P6/P8` 顺序：

```text
DS_mu, KF_mu, DS_sigma, KF_sigma, r_DS, LNS_ksi, num_clusters, num_rays
```

v3.1 首先确认 P8 在更多场景中的可靠性，再逐步研究角度、空间和动态相关参数。每增加一个参数，都必须同时说明：物理意义、单位、标签来源、归一化、缺失补齐来源、生成器映射和对 CIR 的敏感度。

**完成标准：** 不把“参数数量更多”误称为“预测更好”；新参数通过端到端验证后才进入正式包。

### v3.1-4：模型与训练策略优化

- 分别优化 GRU、LSTM、TCN 的隐藏维度、层数、学习率、Dropout、早停和输入窗口；
- LSTM/双向网络只在物理任务允许时使用；双向模型不能用于真正未来外推；
- 在研究型 Adapter 中比较 DLinear/NLinear、小型 Transformer、PatchTST、iTransformer 等候选；
- 新模型只有通过同一套多路线验证门槛才可进入正式候选池；
- 研究参数损失权重、置信度和分布外检测，防止个别参数或个别场景明显变差。

**完成标准：** 每个候选都能与 Persistence、Linear 在相同验证划分下公平比较，并有多随机种子报告。

### v3.1-5：ModelRegistry v2 与安全回退

- 按任务、参数包、输入/输出形状、场景范围和数据版本保存推荐模型；
- 自动选择记录选择来源、证据摘要、模型版本、参数包、数据版本和兼容性检查；
- 高级用户仍可手选兼容模型，但界面须标明“手动选择，非系统推荐”；
- 模型不兼容、置信度低或资源不足时明确失败或回退；不得静默换模型；
- 自动路径继续禁止读取本次目标区域 Ground Truth。

**完成标准：** 注册表加载严格、可复现、可回退；推荐模型可以是神经网络，也可以是简单基线。

### v3.1-6：端到端精度与准确性验证

- 参数级：原始单位误差、综合 NRMSE、分参数误差；
- CIR/CTF 级：复数系数、时延、功率分布；
- 特性级：PDP、时延扩展、角度/空间、多普勒/时间等仅在数据支持时计算；
- 固定生成器随机种子，区分生成器随机波动和预测误差；
- 分析参数敏感度：哪些参数误差真正影响最终 CIR；
- 报告内插、外推、不同场景、不同路线和不同数据维度的结果。

**完成标准：** Benchmark 在软件外部独立运行，最终 Test 不参与训练、模型选择、生成器标定或在线适配。

### v3.1-7：产品接入与发布

- 正式 UI 自动读取新版注册表，并如实显示实际模型、参数包、版本和简短原因；

- 更新使用手册、接口文档、限制说明和 Release Notes；
- 将内置 Full 6GPCM 连同完整性哈希纳入 GitHub Release/源码包，发布前用全新目录执行一次零配置安装验收；
- 复用 v3.0 Step 12 已完成的可配置 Tx/Rx/Nt Full 6GPCM 公共 API Adapter，并在正式验收后继续接入 QuaDRiGa 等候选；普通模式继续执行“逐候选兼容性与可用性检查，全部失败后才报错”；
- 回归 v3.0 的输入、生成、导出、Manifest、普通/高级模式和手动选择不静默替换规则。

**完成标准：** 精度改进不会破坏 v3.0 已经完成的端到端平台能力。

## 6. 成功如何定义

v3.1 的成功不等于“必须把默认模型改成 TCN、LSTM 或 GRU”。成功应满足：

- 若神经网络确实更好，平台有充分、可复现的证据升级默认模型；
- 若简单基线仍更好，平台诚实保留简单基线；
- 任何推荐都不泄漏目标区域答案；
- 改进后的参数预测能在生成 CIR 后仍保持有意义的信道特性质量；
- 从全新 Git Clone 或 GitHub ZIP 启动时，普通用户无需手动配置 Full 6GPCM 路径；
- 用户可以从 Manifest 追溯一次结果为何选择该模型。

## 7. v3.0 当前真实起点

v3.1 不能把 v3.0 已经完成的“模型骨架”误写成“已经具备成熟泛用模型”。当前真实情况是：

1. Python/PyTorch 已实现 GRU、LSTM、TCN、Persistence 和 Linear；
2. Step 10 已保存基于小型确定性公开 fixture 的内插/外推参考权重和 ModelRegistry；
3. 参考神经网络输入输出为 `[N,16,2] → [N,4,2]`，只预测 `DS_mu/KF_mu`；
4. GRU/LSTM 使用序列编码器和线性多步输出头；TCN 使用三层膨胀率 `1/2/4` 的因果残差卷积编码器和线性输出头；
5. 内插使用共享的左右双侧编码，外推使用因果编码；
6. Step 11ABC 在更严格的 40 路线、多种子和端到端验证后，没有批准神经网络进入正式产品；
7. 因此 v3.0 正式 App 当前只批准 Persistence：外推使用 P6，内插使用 P8；
8. 当前产品中的 P6/P8 Persistence 是“已知区标定参数保持不变”，不是神经网络动态预测全部参数；
9. Step 10 的头部微调代码、`off/auto/force`、早停、验证改善门槛和回滚均已存在，但正式 App 当前没有把上传数据接入该神经网络适配链路。

所以，v3.1 的起点是“可调用、可训练、可测试的模型与微调基础设施已经存在”，而不是
“一个已经在真实多场景数据上证明泛化能力的通用预训练模型已经完成”。

## 8. 参数预测扩展计划

### 8.1 先回答预测多少个参数

按固定顺序比较：

```text
P2 = DS_mu, KF_mu
P4 = P2 + DS_sigma, KF_sigma
P6 = P4 + r_DS, LNS_ksi
P8 = P6 + num_clusters, num_rays
```

每个包分别完成参数级、CIR 级和信道特性级评价。不能因为 P8 参数更多就自动判定 P8 更好。

### 8.2 参数敏感度和消融

1. 每次只扰动一个参数，固定生成器随机种子；
2. 观察复数 CIR、PDP、RMS 时延扩展、角度、空间相关和多普勒的变化；
3. 计算某个参数预测误差对最终 CIR 的影响；
4. 删除一个参数重新训练，检查性能是否真正下降；
5. 只把标签可靠、可以归一化、能够映射到生成器且端到端有收益的参数加入正式包。

### 8.3 后续扩展参数

P8 验证稳定后，再分别研究：

- 角度域参数；
- 空间相关参数；
- 多普勒和动态参数；
- 路径/簇出生、消失与漂移参数。

必要时研究“物理参数预测 + 复数 CIR 残差修正”的混合方案，但直接复数残差模型必须保持
目标区域隔离，并与纯参数路线在相同 Benchmark 下比较。

## 9. 模型与训练实施计划

### 9.1 数据优先

- 扩充路线、LOS/NLOS、频段、速度、天线和遮挡状态；
- 按整条路线/场景分组切分，禁止相邻滑窗跨 Train/Validation/Test；
- 实测数据只在授权后用于本地独立验证或明确隔离的适配实验；
- 数据、模型、随机种子、许可证和哈希由 Experiment Manifest 记录。

### 9.2 公平候选池

正式比较：Persistence、Linear、AR、Kalman、GRU、LSTM、TCN、DLinear/NLinear；
小型 Transformer、PatchTST、iTransformer 先作为研究候选，不预设一定优于简单模型。

### 9.3 内插与外推分开

- 外推只能使用历史已知区，模型必须因果；
- 内插可以使用目标两侧的已知区，允许共享双侧编码；
- 两类任务使用独立权重、归一化、Registry 和验收报告。

### 9.4 系统调参

对输入窗口、预测跨度、隐藏维度、层数、卷积通道、卷积核、Dropout、学习率、批大小、
损失权重和早停分别搜索。多参数损失按训练集尺度和 CIR 敏感度设计，避免某一大数值参数主导损失。

## 10. 上传数据微调实施计划

1. 加载已经通过离线准入的泛用模型；
2. 只从用户上传数据的已知区域构造适配样本；
3. 已知区再分为适配训练和适配验证，目标区永不参与；
4. 第一版只解冻输出头，不修改整个编码器；
5. 采用最小样本数、最大时间、早停和最小相对改善门槛；
6. 适配验证没有改善时回滚到原始泛用模型；
7. Manifest 记录是否尝试、是否接受、更新了哪些参数和回滚原因；
8. 分布外或数据不足时直接使用安全基线，不强行微调。

### 11.1 复用 v3.0 Step 14 MAT/HDF5 转换向导

MAT 转换向导已提升为 v3.0 Step 14 正式交付，不再作为 v3.1 的新功能。v3.1 只负责：

- 使用转换后的标准 v3 HDF5 建立训练、验证和本地适配数据；
- 当 v3.1 增加新预测参数或新数据来源时扩展转换 Manifest，而不破坏 v3.0 合同；
- 对新的授权实测格式增加显式 Adapter，继续禁止猜测物理含义或从功率恢复相位。

### 11.2 Full 6GPCM 随仓库分发与自动发现

- 正式采用 `third_party/full_6gpcm/` 作为内置且版本固定的运行副本；
- 完整上游源码包和必要静态资源直接提交到 GitHub，不使用 Submodule，不要求用户执行额外下载脚本；
- 启动器根据项目根目录解析绝对路径，避免依赖 MATLAB 当前工作目录，也要覆盖带空格或中文的安装路径；
- 普通用户始终走内置副本；高级用户才可显式覆盖为其他外部版本；
- 技术完整性记录保存版本和哈希；核心文件不由 ChanAI Pulse 修改；
- Full 6GPCM 核心保持原样，参数映射、输入输出标准化、异常解释和候选回退全部位于 ChanAI Pulse Adapter；
- 发布验收必须在一份全新 Clone 和一份 GitHub ZIP 解压副本上各运行一次，确认没有本机历史路径依赖。

### 11.3 时间轴和频率轴目标任务

重构 TaskRequest、PredictionResult、目标坐标映射、输出形状和 Benchmark 对齐，使用户能够在
`Nt` 或 `Nf` 内部设置内插/外推目标。目前的“可导入、可画图”不能冒充已经支持目标生成。

### 11.4 QuaDRiGa 正式 Adapter

在不复制或修改上游核心的前提下，完成版本/许可证检查、场景/轨迹/阵列映射、标准 CIR/CTF
输出、Manifest 和自动兼容性测试，再加入生成器自动候选链。

## 12. 研究基础设施与 Benchmark 增强

### 12.1 Experiment Manager

一次实验自动保存配置、数据版本、分组切分、模型、归一化、随机种子、指标、图、日志、
生成器信息和报告，使模型准入结果可以完整复现。

### 12.2 Benchmark 后续增强

- 多随机实现的均值、标准差和置信区间；
- 最差路线、尾部误差和按场景分组结果；
- PDF 报告和跨数据集汇总；
- CPU/GPU/内存与推理耗时；
- 参数敏感度和消融图；
- 正式 GRU/LSTM/TCN 排名。

Benchmark 仍保持独立 App；上述准确度信息不得回流到正式模块三页面。
