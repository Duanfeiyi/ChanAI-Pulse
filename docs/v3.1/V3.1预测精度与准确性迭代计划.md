# ChanAI Pulse v3.1：预测精度与准确性迭代计划

> 状态：规划中；在 v3.0 正式平台、外部 Benchmark 和发布验收完成后启动。
> 版本定位：v3.1 是在 v3.0 稳定平台基础上的**预测精度与科学验证迭代**，不是重新设计平台 UI。
> 关联：`docs/v3.0后续工作Steps.md` 的 Step 11A/11B/11C、Step 13、Step 14。

## 1. 为什么需要 v3.1

v3.0 的首要目标是建立可信、可追溯、能生成预测 CIR 的完整平台链路：

```text
输入信道和任务
→ 参数标定
→ 参数预测
→ 6GPCM 生成预测 CIR
→ 合法信道特性展示与导出
```

当前 Step 11ABC 的验证结果中，自动选择了 `Persistence`（延续最后一个已知值）作为默认预测器。它并不是“AI 功能失败”，而是说明当前合成路线平滑、预测跨度短时，简单基线尚未被 GRU、LSTM、TCN 稳定超越。

v3.1 的任务就是在更多数据、更严格的验证和更完整的参数目标下，判断神经网络能否真正、稳定地超过基线；只有证据充分时，才升级系统的默认模型。

## 2. v3.1 的边界

### 要做

- 扩充泛用预训练数据、场景和路线覆盖；
- 提升 GRU、LSTM、TCN 及经验证研究型候选的预测精度；
- 扩展预测参数包；
- 建立更严格的 ModelRegistry v2；
- 通过软件外部 Benchmark 验证“参数 → CIR → 特性”的端到端质量；
- 在不改变普通用户操作习惯的前提下，让正式 UI 显示新的真实推荐模型和理由。

### 不做

- 不因为 v3.1 而改变 v3.0 的 CIR/CTF 数据合同；
- 不把 Ground Truth、RMSE、NRMSE 或模型排名放入正式模块三；
- 不修改完整版 6GPCM 核心；
- 不把私有实测数据、受限数据或大规模训练资产上传到公开 Git；
- 不保证“必须由神经网络取代 Persistence”。基线持续胜出时，继续使用基线是正确结果。

## 3. 自动模型选择：未来怎样从 Persistence 升级为 GRU、LSTM 或 TCN

这里有两个不同层次：

| 层次 | 做什么 | 不能做什么 |
|---|---|---|
| 离线训练与验证 | 用冻结的训练/验证路线比较模型，生成新版 ModelRegistry | 不能用最终测试集反复调参 |
| 用户实际预测 | 根据任务与数据合同读取已经冻结的推荐模型 | 不能读取本次目标区域真实答案后临时挑模型 |

### 3.1 离线比较流程

对每个兼容组合独立比较：

```text
任务类型（内插/外推）
× 参数包（P2/P4/P6/P8 或后续扩展包）
× 场景/数据版本
× 模型（Persistence、Linear、GRU、LSTM、TCN）
```

每个神经网络至少使用多个随机种子，并在路线级、场景级隔离的验证数据上比较。比较时同时看：平均误差、最差路线、胜出路线比例、随机种子波动、推理成本和端到端 CIR 特性。

### 3.2 第一版升级门槛

沿用 Step 11ABC 已冻结的安全门槛，直到 v3.1 启动会议正式调整：

1. 神经网络的平均 NRMSE 至少比最佳简单基线改善 10%；
2. 至少在 60% 的验证路线中胜出；
3. 任一路线的误差不得超过基线的 2 倍；
4. 多随机种子结果不能明显不稳定；
5. 经过 `预测参数 → 6GPCM → CIR/CTF → 信道特性` 的端到端检查后仍然合格；
6. 上述选择完成后冻结，最终 Test 只负责评分，不能倒回去继续挑模型。

满足全部条件的候选中，再按验证表现、最差路线表现、稳定性和资源成本选择最佳模型。例如：

```text
外推 + P6：TCN 满足全部门槛且综合最佳 → 自动推荐 TCN
内插 + P8：LSTM 满足全部门槛且综合最佳 → 自动推荐 LSTM
某任务没有神经网络过线 → 自动推荐 Persistence 或 Linear
```

这份结果写入版本化 `ModelRegistry`。正式 UI 只显示注册表的真实选择和简短理由，不能为了看起来更“AI”而隐藏基线。

## 4. 工作包

### v3.1-0：建立可比较的 v3.0 基线

- 固定 v3.0 发布版本、数据合同、Step 13 Benchmark 与模型/生成器 Manifest；
- 保存当前外推 P6 + Persistence、内插 P8 + Persistence 的基线报告；
- 记录硬件、Python/MATLAB 版本、Full 6GPCM 版本和随机种子；
- 明确哪些指标属于产品外 Benchmark，哪些只作为产品内状态文本。

**完成标准：** 同一输入可以复现 v3.0 基线结果；没有人可以通过更换测试划分来“制造提升”。

### v3.1-1：扩充训练与验证语料

- 以完整 6GPCM 多场景、多速度、多频段、多天线配置生成器真值为主要可公开复现来源；
- 增加更长路线、突变/遮挡、不同 LOS/NLOS、动态和空间变化；
- 实测数据仅在取得授权后用于本地外部验证或明确隔离的适配研究；
- 继续按路线/场景组切分，禁止相邻滑窗跨 Train/Validation/Test；
- 所有下载、缓存和派生训练资产保存到 D 盘工作资产目录，不进入 Git。

**完成标准：** 数据版本、来源、许可证、分组切分和规模可追溯；训练/验证/测试没有泄漏。

### v3.1-2：扩展预测目标参数

v3.0 已冻结 `P2/P4/P6/P8` 顺序：

```text
DS_mu, KF_mu, DS_sigma, KF_sigma, r_DS, LNS_ksi, num_clusters, num_rays
```

v3.1 首先确认 P8 在更多场景中的可靠性，再逐步研究角度、空间和动态相关参数。每增加一个参数，都必须同时说明：物理意义、单位、标签来源、归一化、缺失补齐来源、生成器映射和对 CIR 的敏感度。

**完成标准：** 不把“参数数量更多”误称为“预测更好”；新参数通过端到端验证后才进入正式包。

### v3.1-3：模型与训练策略优化

- 分别优化 GRU、LSTM、TCN 的隐藏维度、层数、学习率、Dropout、早停和输入窗口；
- LSTM/双向网络只在物理任务允许时使用；双向模型不能用于真正未来外推；
- 在研究型 Adapter 中比较 DLinear/NLinear、小型 Transformer、PatchTST、iTransformer 等候选；
- 新模型只有通过同一套多路线验证门槛才可进入正式候选池；
- 研究参数损失权重、置信度和分布外检测，防止个别参数或个别场景明显变差。

**完成标准：** 每个候选都能与 Persistence、Linear 在相同验证划分下公平比较，并有多随机种子报告。

### v3.1-4：ModelRegistry v2 与安全回退

- 按任务、参数包、输入/输出形状、场景范围和数据版本保存推荐模型；
- 自动选择记录选择来源、证据摘要、模型版本、参数包、数据版本和兼容性检查；
- 高级用户仍可手选兼容模型，但界面须标明“手动选择，非系统推荐”；
- 模型不兼容、置信度低或资源不足时明确失败或回退；不得静默换模型；
- 自动路径继续禁止读取本次目标区域 Ground Truth。

**完成标准：** 注册表加载严格、可复现、可回退；推荐模型可以是神经网络，也可以是简单基线。

### v3.1-5：端到端精度与准确性验证

- 参数级：原始单位误差、综合 NRMSE、分参数误差；
- CIR/CTF 级：复数系数、时延、功率分布；
- 特性级：PDP、时延扩展、角度/空间、多普勒/时间等仅在数据支持时计算；
- 固定生成器随机种子，区分生成器随机波动和预测误差；
- 分析参数敏感度：哪些参数误差真正影响最终 CIR；
- 报告内插、外推、不同场景、不同路线和不同数据维度的结果。

**完成标准：** Benchmark 在软件外部独立运行，最终 Test 不参与训练、模型选择、生成器标定或在线适配。

### v3.1-6：产品接入与发布

- 正式 UI 自动读取新版注册表，并如实显示实际模型、参数包、版本和简短原因；
- 模块三仍不展示任何当前任务的准确度图；
- 更新使用手册、接口文档、限制说明和 Release Notes；
- 复用 v3.0 Step 12 已完成的可配置 Tx/Rx/Nt Full 6GPCM 公共 API Adapter，并在正式验收后继续接入 QuaDRiGa 等候选；普通模式继续执行“逐候选兼容性与可用性检查，全部失败后才报错”；
- 回归 v3.0 的输入、生成、导出、Manifest、普通/高级模式和手动选择不静默替换规则。

**完成标准：** 精度改进不会破坏 v3.0 已经完成的端到端平台能力。

## 6. 成功如何定义

v3.1 的成功不等于“必须把默认模型改成 TCN、LSTM 或 GRU”。成功应满足：

- 若神经网络确实更好，平台有充分、可复现的证据升级默认模型；
- 若简单基线仍更好，平台诚实保留简单基线；
- 任何推荐都不泄漏目标区域答案；
- 改进后的参数预测能在生成 CIR 后仍保持有意义的信道特性质量；
- 用户可以从 Manifest 追溯一次结果为何选择该模型。
